# How triage decides, and why it is justified

Generated by `scripts/triage_justification.py` (numbers from `reports/metrics/*.json` and the replayed days); equations are implemented and tested in `echos/orchestrator/triage_theory.py`. Triage stage 1 (`echos/orchestrator/triage.py`) is a rule function, not a trained model. This page says why those rules are a sound way to decide, and where they are not.

## The algorithm: severity = the maximum over independent rules

```
s(x) = max( s_urgent(x), s_monitor(x), s_gap(x) )          NORMAL < MONITOR < URGENT

s_urgent : fall score >= 0.8 AND post-fall inactivity      OR   a vital sign beyond its absolute clinical limit
s_monitor: vitals score >= tau_v   OR   agitation score >= tau_b   OR   an unconfirmed fall
s_gap    : sensor gap / quality unchecked / output missing / no vitals for > 7 days      (never NORMAL)
```

**E1, why a maximum.** Each rule asks one question about one source, so a new source or rule can only add evidence, never hide it. This gives properties that can be checked rather than argued. On a grid of 4096 input combinations, run through the real `triage()`: raising any score or switching on a flag never lowered the status (0 violations); a data gap was never NORMAL (0); a critical vital was always URGENT whatever the model score (0); a missing detector output was never NORMAL (0). All hold = True.

## Why a threshold on a calibrated score

For a detector with a calibrated score p = P(event | x), alerting has the lower expected cost exactly when

```
p * c_miss  >  (1 - p) * c_fa      <=>      p  >  tau = c_fa / (c_fa + c_miss)      <=>      c_miss / c_fa = (1 - tau) / tau
```

(E2; verified numerically in `tests/test_triage_theory.py`: on synthetic calibrated scores the cost-minimising threshold equals c_fa/(c_fa+c_miss).) ECHOS does not know the real costs, so it fixes the false-alert budget instead and reads the cost off the threshold (E3, the Neyman-Pearson form: the highest recall at a fixed false-alert rate is a threshold on the score):

```
tau_k = min { t : FA_k(t) <= B_k }          vitals: B <= 1 alert / patient-week;   behaviour: B <= 10% of patient-days
```

| Detector | threshold tau | implied c_miss / c_fa | Brier skill (calibrated) | recall at tau | precision at tau |
|---|---|---|---|---|---|
| Vitals | 0.278 | 2.6 | 0.402 | 0.721 | 0.569 |
| Behaviour | 0.129 | 6.75 | 0.085 | 0.509 | n/a |

Reading: at the chosen budget the vitals rule treats one missed event as worth about 2.6 false alerts and the behaviour rule about 6.75. Brier skill = 1 - Brier / Brier(prevalence): vitals 0.402 (the score is informative and can be read as a probability), behaviour 0.085 (barely above the base rate, so its cost reading is weak and the rule is the weakest in the system). These costs are implied, not measured: nothing here estimates what a missed event really costs.

## Why a fall needs inactivity as well

The fall detector scores a 2.5 s window; most false alarms are vigorous daily movement. Requiring post-fall inactivity (rule `fall >= 0.8 AND inactive`) trades a little sensitivity for far fewer false alarms: at the same threshold sensitivity goes 0.952 -> 0.918 (cost 0.034), false alarms per hour 1.158 -> 0.421 (x2.75 fewer). An unconfirmed fall is still MONITOR, so it is not lost. SisFall adult trials; ADL trials are short and vigorous, so false alarms per hour overstate daily life.

## Alert load: what the budget does and does not bound

If detectors raise alerts independently with day-rates a_k, the share of days with at least one alert and the weekly load are

```
a_day = 1 - prod_k (1 - a_k)          alerts / patient-week  <=  sum_k B_k          (E4: independence, union bound)
```

On the 1266 replayed days (180.9 patient-weeks): the model alerts are bounded by 1.694 per patient-week by the budgets. Measured share of days by source: vitals model 0.174, behaviour model 0.1, possible fall 0.016, data gap 0.043, urgent fall 0.042, urgent vitals 0.003. MONITOR days measured 0.288 vs independence prediction 0.3 (close, so independence is a fair approximation here); without a data gap 0.244 of days are MONITOR, so the load comes from the model alerts, and data gaps add only 0.043 of days. The vitals rule raised 1.216 alerts per patient-week on these days against its budget of 0.999 measured on out-of-fold data: the replay is a subset (20 patients, 1266 of the 2797 patient-days the budget was set on), so the budget holds on the data it was set on and is exceeded on this subset: a budget is a design target, not a guarantee. URGENT: 0.315 days per patient-week, falls INJECTED from SisFall in the replay (TIHM has no falls) (urgent fall 0.042 of days), so this figure is a test load, not a rate of real falls.

## What this does not show

- Costs are IMPLIED by the thresholds (tau = c_fa/(c_fa+c_miss)); nothing here estimates the real cost of a missed event.
- A cost reading of a threshold is only valid to the extent the score is calibrated: Brier skill is the evidence, and behaviour is barely above the base rate.
- Event labels (Labels.csv) are of unverified provenance, so recall / precision are weak evidence; about 49 labelled patients: wide intervals.
- The rules, the budgets and the inactivity requirement are design choices backed by the numbers above; none is validated against real clinical outcomes.
