# Components: agents, tools and infrastructure

Generated by `scripts/docgen/make_components_doc.py` from `echos/components.py`; the API (`GET /api/components`) and the web app (How it works) read the same registry.

ECHOS watches the vital signs and home activity sensors of people living with dementia. It alerts the caregiver and clinician at once on a red-flag reading, and every day tells a small clinical team who to review and why, in plain words. Decision support, not a diagnosis; no model decides an emergency.

## Agents

Agent: its own process with a goal, a persistent belief (memory), its own decisions, and messages to the other agents. It learns from feedback.

### Patient Monitor (`patient_monitor`)

One per person. Learns what is usual for this person (blood pressure, pulse, daily activity by time of day), scores each day, sends an URGENT message on a red-flag reading and a review request with plain-words reasons after the day's feedback.

- **Takes in:** the day's readings and activity windows; FEEDBACK messages (clinician / study outcome)
- **Produces:** urgent -> Care agent; review_request (vitals risk, agitation risk, reasons) -> Review Coordinator
- **If it fails:** the supervisor restarts it; it resumes from its saved memory and checkpoint, and nothing is scored twice
- **Never:** send email itself, or decide who is reviewed

### Review Coordinator (`review_coordinator`)

Shares the clinical team's K daily reviews across everyone: priority = how far each person's risk is above its own base rate, with a fairness floor so nobody goes unseen for more than a week.

- **Takes in:** review_request messages; the day's close
- **Produces:** the daily review list; assign -> Care agent; review_decision -> Patient Monitors
- **If it fails:** the supervisor restarts it; while a monitor is down it waits instead of allocating with missing requests
- **Never:** downgrade an URGENT case or send anything itself

### Care agent (`care`)

Makes sure every urgent case and every assigned review reaches a person: queues the fixed-template alert at once, tracks acknowledgement, escalates when nobody answers, opens review tasks, and passes the clinician's outcome back as FEEDBACK.

- **Takes in:** urgent and assign messages; clinician outcomes
- **Produces:** alert e-mails (dry run unless configured), review tasks, feedback -> Patient Monitor
- **If it fails:** the outbox keeps every alert; a restarted Care agent resumes sending and escalating from the database
- **Never:** change a risk score or a review decision

## Tools

Tool: a method an agent calls. It computes; it never decides, sends or remembers anything on its own.

### Personal baseline (tool) (`personal_baseline`)

Normal-Inverse-Gamma model of each person's usual reading: 'systolic 172 vs usual 138 (+3.1 SD)'.

- **Takes in:** the person's past readings
- **Produces:** usual, z-score, surprise
- **If it fails:** a new person starts at the population usual
- **Never:** use future readings

### Personal event rate (tool) (`event_rate`)

Beta-Bernoulli rate of confirmed BP / pulse events with an empirical-Bayes prior: the vitals review priority, with a 95% credible interval.

- **Takes in:** confirmed outcomes so far
- **Produces:** 3-day risk
- **If it fails:** falls back to the pooled rate
- **Never:** claim to forecast a new episode

### Agitation detector (tool) (`agitation_detector`)

Gradient-boosted trees on room / door sensor windows against the person's usual for that time of day, calibrated.

- **Takes in:** activity window features + personal same-slot history
- **Produces:** probability + the features furthest above usual
- **If it fails:** a window with no history uses raw counts only
- **Never:** trigger an urgent alert

### Alert rules (tool) (`alert_rules`)

URGENT = NEWS2 red scores or BP >= 180/120 (no model involved). TIHM's own daily-check limits are attention notes only.

- **Takes in:** one reading
- **Produces:** reasons
- **If it fails:** missing values never fire
- **Never:** use a learned model

## Infrastructure

Infrastructure: keeps the agents running and connected.

### Message bus (`bus`)

SQLite table agent_message: the only channel between the agents (who told whom what, and when).

- **Takes in:** post()
- **Produces:** poll() / done()
- **If it fails:** unconsumed messages wait; nothing is lost on restart
- **Never:** drop an unhandled message

### Supervisor + watchdog (`supervisor`)

Restarts an agent process whose heartbeat stops or whose cursor stalls; the watchdog restarts the whole runtime if it dies.

- **Takes in:** heartbeats
- **Produces:** restarts (restart_log)
- **If it fails:** the API reports 'runtime not running'
- **Never:** change data

### Replay controller (`replay`)

Replays real TIHM days (readings, activity windows, then the study's confirmed outcomes) for the demo cohort; can inject one reading for a demo.

- **Takes in:** TIHM files
- **Produces:** event_log rows
- **If it fails:** pauses; state kept in sim_state
- **Never:** invent data (only the injected demo reading)

## How they talk

Only through the SQLite message bus (`agent_message`, `echos/team/bus.py`):

- Patient Monitor -> Care agent: `urgent` (a red-flag reading)
- Care agent -> Patient Monitor: `feedback` (the day's confirmed outcome: the learning signal)
- Patient Monitor -> Review Coordinator: `review_request` (risks + plain-words reasons)
- Review Coordinator -> Care agent: `assign` (one per selected person); -> Patient Monitors: `review_decision`
- Clinician (API) -> Care agent: `clinician_outcome`

The web app shows the live trace on the *Agents* page and each person's messages on their page.
